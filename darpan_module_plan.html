LAYER 3 · ANALYTICS
M5
Stress score engine 2–3 wks
Composite index sub-components
Complaint intensity — complaints per branch or per ₹ crore deposits (size-normalized)
Trend velocity — YoY growth rate, category-weighted
Resolution quality — disposal rate, avg resolution time, % maintainable complaints
Award severity — compensation amounts vs peer-group median
Concentration risk — category/regional clustering flag (spike in one area vs broad stress)
Normalization approach
Z-scores or percentile rank within peer group (PSU / private / cooperative / foreign — not raw-scale cross-comparison)
Documented weighting rationale — this is the piece regulators will interrogate most
Tech stack
Pythonpandasnumpyscipy
Depends on
M3 — complaints_annual + bank_financials loadedM4 — pipeline confirmed stable
M6
Anomaly detection engine 1–2 wks
Detection methods (in order of implementation)
Baseline: rolling z-score on category-wise complaint time series per bank — flag >2–3σ deviations
Seasonal decomposition (STL) on complaint volumes — separate trend / seasonal / residual
Change-point detection via ruptures library for structural breaks in series
Isolation forest layer once baseline is validated and interpretable
Tech stack
statsmodelsscikit-learnruptures
Depends on
M5 — stress score stable, peer grouping done
Start simple. Explainability matters more than model sophistication for a regulatory tool. Don't jump to isolation forest before the z-score baseline is validated.
LAYER 4 · INTELLIGENCE
M7
Policy brief generator 2–3 wks
Components
Structured retrieval layer — queries Postgres (not raw PDFs) for bank/period/category context
Fixed output schema: Executive Summary → Trend Analysis → Stress Score Rationale → Peer Positioning → Anomalies Flagged
LLM fills narrative around pre-computed numbers only — never computes or invents figures
Pydantic models enforcing report schema + data-provenance footer (source years, tables referenced)

LangChainPydanticAnthropic APIFastAPI
Depends on
